## Purpose

This workbook translates concepts from **The New SDLC With Vibe Coding** into practical security requirements for organizations that use AI coding agents, autonomous development assistants, code-generation tools, and agentic software-development workflows.

The tool is intended to help security, engineering, and governance teams evaluate how AI coding agents are authorized, constrained, monitored, tested, and integrated into the software development lifecycle.

## Security Areas

The workbook supports assessment and planning across areas such as:

- Governance, ownership, acceptable use, and risk classification
- Identity, authentication, authorization, and least privilege
- Repository, branch, file, command, tool, and network access boundaries
- Human approval for sensitive or irreversible actions
- Secret, credential, source-code, and regulated-data protection
- Dependency, package, model, plugin, tool, and software supply-chain security
- Sandboxing, execution isolation, environment separation, and egress control
- Prompt injection, malicious instructions, unsafe code generation, and agent manipulation
- Code review, testing, security scanning, policy enforcement, and release gates
- Logging, traceability, evidence retention, attribution, and change provenance
- Runtime monitoring, anomaly detection, incident response, rollback, and recovery
- Metrics, ownership, implementation status, exceptions, and residual risk

## Recommended Use

1. Identify the coding agents, repositories, development environments, models, tools, identities, and workflows in scope.
2. Classify agent capabilities by potential impact, including read, write, execute, deploy, approve, and administer permissions.
3. Select applicable requirements and assign owners, implementation status, evidence, and target dates.
4. Validate technical controls through secure testing, policy checks, sandbox exercises, and controlled failure scenarios.
5. Integrate approved requirements into architecture standards, CI/CD controls, access policies, and incident-response procedures.
6. Reassess the workbook after material changes to models, prompts, tools, repositories, permissions, or deployment architecture.

## Important Note

The workbook is an assessment and design aid. Requirements must be tailored to the organization's software-development model, risk tolerance, data classification, regulatory obligations, and production architecture.
